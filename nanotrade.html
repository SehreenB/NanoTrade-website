FAQ

Frequently
Asked Questions

You have questions. We have answers.

How does on-chip ML work without a GPU?

The ML model is a compact 3-layer MLP (16→8→6) trained offline and quantized to 16-bit fixed-point weights stored in 32KB of on-chip ROM. Inference runs via pipelined fixed-point matrix multiplications directly in silicon — no floating point, no OS, no GPU needed. The full inference path completes in 100–250ns.

How is NanoTrade 100× cheaper than FPGAs?

FPGAs cost $50,000+ because they're programmable general-purpose devices. NanoTrade is a custom ASIC designed for exactly one task. At volume, ASICs are orders of magnitude cheaper. A 100-unit exchange deployment costs $50,000 with NanoTrade versus $5,000,000 with FPGAs.

What anomalies can the chip detect?

The 6-class MLP classifies: Flash Crashes, Spoofing (fake large orders to move prices), Pump & Dump (coordinated inflation), Wash Trading (self-trades for fake volume), Liquidity Crises (evaporating order book depth), and Volatility Spikes. It monitors 16 features including price delta, volume, bid-ask spread, cancel rate, and order book imbalance.

What happens when a RED alert triggers?

When the circuit breaker escalates to RED, the chip sends a HALT signal back to the matching engine input within 1ms, stopping new order processing. A 5-minute cooling period timer starts. All events are logged to the on-chip FIFO audit buffer for regulatory submission and the exchange operator is simultaneously notified via the 128-bit output bus status field.

Can the ML model be updated for new anomalies?

The current chip uses fixed ROM weights trained on MIT/NYSE historical datasets plus synthetic anomaly scenarios. Future versions will support writable flash for field weight updates. The 16→8→6 architecture can be retrained offline and re-flashed without hardware changes.

What process node is this built on?

The chip targets the Sky130 130nm open-source PDK via TinyTapeout. While 130nm is older than commercial HFT silicon, it's sufficient for this demonstrator — latency is dominated by algorithmic pipeline depth, not transistor switching speed. Production versions would target 28nm or smaller for sub-50ns matching.
